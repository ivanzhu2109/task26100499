# reuse — 学术查重连续复用片段定位库

定位待查文档中连续复用自语料来源的片段，返回每段证据的来源编号与两侧原文区间。
只处理连续复用，不做整篇评分或改写识别。

## 业务规则

- 词 = 最长连续 ASCII 英文字母串，匹配忽略大小写；其余字符均为分隔符，分隔符差异不影响逐词匹配。
- 对待查文本的每个词起点，求能在**同一份来源**中逐词连续出现的最长片段；不足 8 词不形成证据，匹配不跨来源边界。
- 同一起点的最长片段命中多份来源时取编号最小者；该来源中出现多次时取起始位置最早者。
- 只返回未被其他候选区间**严格包含**的证据（跨来源生效）；相互交叠但互不包含的片段分别保留。
- 坐标从 0 开始，以 Unicode 码点计数，左闭右开；区间覆盖首词首字符至末词末字符（含中间分隔符）。

## API

```go
b := reuse.NewBuilder()
_ = b.AddDocument(1, "source text one")   // id 为唯一正整数
_ = b.AddDocument(2, "source text two")
idx, _ := b.Build()                        // 整批构建只读索引（一次性开销）

for _, e := range idx.Query("paper text") { // Index 只读，可并发查询
    // e.DocID                               来源编号
    // e.QueryStart, e.QueryEnd              待查文本码点区间 [start, end)
    // e.SourceStart, e.SourceEnd            来源文本码点区间 [start, end)
}
```

## 算法与复杂度

- 语料词序列（文档间以唯一分隔符隔开）上构建**后缀数组**（前缀倍增 + 基数排序，O(n log n)）。
- 每个待查词起点：二分后缀数组的插入位置得到最长匹配长度，再二分出该最长前缀的后缀区间，
  用**区间最小查询**（分块 + 稀疏表）按 (来源编号, 起始位置) 取出最优命中。
  词序列比较用双 64 位滚动哈希（两个独立基）加速，碰撞概率可忽略。
- 候选区间按起点扫描做严格包含过滤，输出证据。
- 构建 O(n log n)，查询每起点 O(log n · log L)，n 为语料词数，L 为匹配长度。

## 验证

```sh
go test ./...          # 正确性：与穷举标准交叉验证（重复词、并列来源、嵌套、交叠、
                       # 跨文档边界、多字节分隔符坐标等）
go run ./cmd/scaletest # 规模验证：2 万份来源 / 480 万词，
                       # 覆盖 60 万次公共 8 词前缀与 1000 词周期重复场景，
                       # 报告证据数量、耗时与峰值内存并对照指标
```

参考指标（Apple Silicon 实测）：构建约 2.5 s、峰值内存 < 400 MiB；
1 万词查询约 15 ms，10 万词查询约 160 ms，均远低于 3 s / 10 s 与 512 MiB 的限制。
