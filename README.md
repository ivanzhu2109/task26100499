# reuse — 学术查重连续复用片段定位库

定位待查论文中**连续复用**自哪份资料的哪段文字，返回可核对的原文区间，
而不是相似度数字。本期只做连续复用定位，不做整篇评分或改写识别。

## 功能与规则

- 词 = 最长连续 ASCII 字母串，匹配忽略大小写；其余字符（含多字节字符）
  均为分隔符，分隔符差异不影响逐词匹配。
- 对待查文本每个词起点，求能在**某一份来源内**逐词连续出现的最长片段；
  不足 8 词不形成证据，匹配不跨来源文档边界。
- 并列处理：先取匹配最长，再取来源编号最小，再取来源内起始位置最早。
- 只返回待查区间未被其他候选**严格包含**的证据（跨来源生效）；
  相互交叠但互不包含的片段分别保留。
- 证据坐标从 0 开始、以 Unicode 码点计数、左闭右开，覆盖首词首字符至
  末词末字符（含中间分隔符，不含两端之外的分隔符）。
- 重复词、常用词、罕见词同等处理：不跳过高频片段、不限制候选来源、
  不做近似。

## 使用

```go
// 整批构建（语料保存在本地目录，构建后只读）
err := reuse.Build("corpus.dir", []reuse.Source{
    {ID: 1, Text: "the quick brown fox ..."},
    {ID: 2, Text: "another source ..."},
})

// 查询
c, err := reuse.Open("corpus.dir")
defer c.Close()
for _, ev := range c.Query(paperText) {
    // ev.SourceID / ev.QueryStart..QueryEnd / ev.SourceStart..SourceEnd
    // 坐标为码点偏移，可直接按 rune 切片核对原文
}
```

## 测试与规模验证

```sh
go test ./...          # 单元测试 + 与穷举标准实现对照的随机测试
go run ./cmd/scalecheck         # 完整规模验证（2 万来源 / 500 万词）
go run ./cmd/scalecheck -quick  # 缩小 10 倍快速自检
```

`scalecheck` 构造含百万次公共 8 词前缀与长段周期重复的语料，
执行 1 万词与 10 万词查询，校验证据内容并报告结果数量、耗时与
峰值内存。参考结果（Apple Silicon）：

| 指标 | 结果 | 要求 |
| --- | --- | --- |
| 构建（一次性） | ~4 s | 不计入查询指标 |
| 1 万词查询 | ~50 ms | < 3 s |
| 10 万词查询 | ~0.6 s | < 10 s |
| 峰值堆内存 | ~380 MiB | ≤ 512 MiB |

## 设计要点

- **索引**：语料词 ID 序列（文档间以保留 ID 0 分隔，匹配天然不跨文档）
  的后缀数组，倍增法 + 计数排序构建。
- **查询**：每个词起点在 SA 上二分定位，双滚动哈希（模 2^64，两组独立
  基数）求语料后缀与待查后缀的最长公共前缀；候选区间由 LCP 单调性
  二分扩张，最优来源由 SA 序上 `(来源编号, 位置)` 的区间最小线段树选出。
- **复杂度**：每词起点 O(log n · log m)，与命中次数无关——同一 8 词
  前缀出现百万次或长段周期重复时性能不退化。
- **内存**：语料侧仅保留词 ID、SA、双前缀哈希、线段树与码点偏移，
  500 万词语料加载后约 240 MiB。
- **坐标**：词区间在分词时以码点记录，多字节分隔符不影响两侧原文截取。

## 限制

- 双哈希理论冲突概率约 2^-128，工程上可忽略；未做逐词复核。
- 语料构建后只读，不支持并发更新与异常中断恢复。
